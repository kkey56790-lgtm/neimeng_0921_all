# 按主任务采集和上传

入口仍为 `run_all_with_point_upload.sh`，实际上传实现为 `scripts/jieguo_uploader.py`。

- 读取 `/inspection/task_status` 中 robot_bridge 发布的 `main_task_name`，开始后建立 `jieguo/任务名_毫秒时间戳/`。
- 到点任务、等待任务（如 `ACTION_WAIT_TIME`）、暂停状态共用同一主任务目录。子任务的 `task_name`、`task_type`、`task_time` 变化不会触发上传或拆目录。
- 检出有效目标后按截图间隔保存带框图片（默认 3 秒），同时保存检测计数。暂停期间也继续采集；未检出有效目标时不生成截图。
- 底盘报告完成/空闲且 `queue_size` 不大于 0 时封存；队列仍有子任务则继续采集。兼容未提供 `queue_size` 的旧底盘，此时依赖其 `task_state` 为整个任务状态。明确停止、取消、失败或切换主任务也会封存已采集结果。
- 封存后统一进入上传队列。`file_upload_request.data` 和 `file_upload_reply.data` 均包含原始 `taskName` 与本次归档的 `taskId`；保留原有 `stationName`、`stationCode` 字段。`content` 沿用检测计数格式。
- 每个批次累计上传失败最多三次（首次加两次重试，失败后间隔 5 秒）。凭证请求超时/拒绝、图片 PUT 失败、成功通知失败或部分图片未完成均算一次；第三次仍失败即删除该任务目录内全部图片、文字和批次记录，继续下一批。失败次数持久化，重启不清零；断网等待连接以及主动退出不计次数。只允许删除结果根目录下独立的已封存任务目录；根目录散放文件、路径异常或仍在采集的目录不会被递归删除。成功后的清理异常只重试清理。
- 程序重启立即补传已封存结果；`COLLECTING` 批次等待底盘状态，同名任务继续写原目录，收到匹配的结束状态才封存。无法确认归属的未结束批次留在本地，不自动假定任务完成。
- 同名任务在收到结束状态后再次开始，会生成新的目录。若程序离线期间同名任务已经结束并重新开始，而底盘没有主任务执行唯一标识，则无法仅凭名称区分这两次执行。

离线验证：在本目录运行 `python -m unittest discover -s tests -v`。覆盖子任务切换、暂停采集、结束统一入队、同名再次执行、重启恢复及上传任务字段；摄像头、底盘状态含义和中台接收字段仍需现场联调。
