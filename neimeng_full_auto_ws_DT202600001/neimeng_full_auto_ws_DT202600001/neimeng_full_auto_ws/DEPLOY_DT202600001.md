# DT202600001 部署说明

## 目标设备与连接关系

- 程序部署主机：客户 RK3588，`192.168.2.101`，SSH 用户 `mile`
- 底盘导航接口：`http://192.168.2.100:7999`
- 云台 ONVIF：`192.168.2.64:80`
- 摄像机 RTSP：`192.168.2.64:554`
- 机器人编码：`DT202600001`

不要把工作区部署到 `192.168.2.100`。该地址是导航控制端和底盘 HTTP 服务端；工作区应放在客户 RK3588（`192.168.2.101`）上。

## 一 部署前连通性检查

先让部署电脑和 1 号车接入同一局域网，然后在部署电脑执行：

```bash
ping 192.168.2.101
ping 192.168.2.100
ping 192.168.2.64
```

登录客户 RK3588 后，再从机器人内部检查底盘和云台：

```bash
ssh mile@192.168.2.101
ping -c 3 192.168.2.100
ping -c 3 192.168.2.64
curl --max-time 3 http://192.168.2.100:7999/sensor_data/base_data
nc -zvw3 192.168.2.64 80
nc -zvw3 192.168.2.64 554
```

以上地址不通时先检查 1 号车路由器、网线和 RK3588 网卡配置，不要直接启动巡检任务。

## 二 上传并解压

在 Windows PowerShell 中，把发布压缩包传到客户 RK3588：

```powershell
scp "D:\1che\neimeng_full_auto_ws_DT202600001.zip" mile@192.168.2.101:/home/mile/
ssh mile@192.168.2.101
```

在客户 RK3588 上保留旧版本并解压新版本：

```bash
cd /home/mile
if [ -d neimeng_full_auto_ws ]; then mv neimeng_full_auto_ws "neimeng_full_auto_ws.bak_$(date +%Y%m%d_%H%M%S)"; fi
unzip neimeng_full_auto_ws_DT202600001.zip
cd /home/mile/neimeng_full_auto_ws
chmod +x run_ubuntu20_all.sh run_ubuntu20_full_auto.sh rknn_yolo/run_yolo.sh
find src independent_systems -type f -name '*.py' -exec chmod +x {} +
```

## 三 安装或核对运行环境

本项目面向 Ubuntu 20.04 和 ROS Noetic。已有环境时只做核对，不要重复安装 ROS：

```bash
source /opt/ros/noetic/setup.bash
python3 -c 'import rospy, requests, PyQt5, yaml, zmq; from onvif import ONVIFCamera; print("ROS Python dependencies OK")'
```

缺少普通系统依赖时执行：

```bash
sudo apt update
sudo apt install -y ros-noetic-desktop-full ros-noetic-catkin python3-requests python3-pyqt5 python3-yaml python3-zmq python3-pip unzip netcat-openbsd
python3 -m pip install --user onvif-zeep
```

RKNN 推理使用已有的 `rknn_yolo` Conda 环境。根据机器上的 Conda 安装位置选择其中一条：

```bash
source /home/mile/anaconda3/etc/profile.d/conda.sh
# 或 source /home/mile/miniconda3/etc/profile.d/conda.sh
conda activate rknn_yolo
python3 -c 'import cv2, numpy, zmq; from rknnlite.api import RKNNLite; print("RKNN dependencies OK")'
conda deactivate
```

如果不存在 `rknn_yolo` 环境，需要安装与该 RK3588 系统镜像匹配的 RKNNLite2 运行库，不能直接使用 x86 电脑上的 Python wheel。

## 五 编译和启动

首次启动会自动在当前机器生成 `build_ubuntu20` 和 `devel_ubuntu20`。包内没有携带旧机器的构建缓存。

Ubuntu 桌面环境使用：

```bash
cd /home/mile/neimeng_full_auto_ws
bash independent_systems/full_system/run_rknn.sh
```

通过 SSH 或无桌面运行时使用：

```bash
cd /home/mile/neimeng_full_auto_ws
NEIMENG_LAUNCH_MODE=inline bash run_ubuntu20_all.sh rknn
```

停止系统使用 `Ctrl+C`。不要同时启动完整系统和三个独立模块，否则会重复占用 ROS 节点名、底盘控制和 ZMQ 端口。

## 六 启动后验收

另开一个终端登录客户 RK3588：

```bash
source /opt/ros/noetic/setup.bash
source /home/mile/neimeng_full_auto_ws/devel_ubuntu20/setup.bash
rostopic echo -n 1 /inspection/robot_telemetry
rostopic echo -n 1 /inspection/health
```

验收时确认：

1. 日志中底盘连接地址为 `192.168.2.100:7999`，持续收到位姿、电量等遥测。
2. 日志中 ONVIF 云台连接地址为 `192.168.2.64:80`，预置位控制正常。
3. YOLO 日志能从 `192.168.2.64:554` 读取 RTSP，并加载 `best_truck.rknn`。
4. ROS 消息中的 `robotCode` 为 `DT202600001`。
5. 空旷安全区域内再测试启停、任务切换、云台随动和回充；首次测试时安排人员随时急停。

如果只验证 ROS 和底盘、不启动识别，可执行：

```bash
bash run_ubuntu20_full_auto.sh enable_ui:=false
```
