# 0919-2.rknn 直播接入

`yolo_live_stream_mqtt.py` 已按新模型的 0–10 类别编号统一 MQTT 返回的中英文名称及直播英文标签。类别顺序来自已确认的源模型 `0919.onnx`：

`chocks, extinguisher, plate, tag, light, support, screw, tank, lamp_broken, box_broken, warning`

直播程序本身不加载模型。部署时同时更新 `rknn_yolo/rtsp_truck.py` 和新增的 `rknn_yolo/run_0919.py`，将 `0919-2.rknn` 放入板端 `rknn_yolo/models/`。停止占用 ZMQ 5566 端口的旧检测进程，在 `rknn_yolo` 目录执行：

```bash
YOLO_DISPLAY=0 python3 run_0919.py
```

另一个终端在 MQTT 脚本目录启动：

```bash
python3 yolo_live_stream_mqtt.py
```

非默认模型路径可通过 `INSPECTION_RKNN_MODEL=/实际路径/0919-2.rknn` 指定。此入口强制使用 `inspection11` 类别表，旧入口保留原配置。

MQTT 保持原有 `get_detection` 查询及 `services_reply` 返回方式，不新增主动上报协议。新模型没有 `tyre`、`truck` 类，依赖这两类的巡检流程不能靠更换名称恢复。

本地检查覆盖类别映射与 MQTT 查询返回；实际推理、摄像头及推流须在 RK3588 板端验证。
